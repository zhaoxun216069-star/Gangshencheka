# 钢神白卡 · 静态多人物档案室（IndexedDB 管理版）

基于《钢神团白卡 25.03.22-4》制作的纯静态网页，可以双击 `index.html` 离线使用，也可以部署到 GitHub Pages。页面内嵌所有 CSS、JavaScript 和规则数据库，无需服务器或外部 CDN。

## 本次更新：住宅自动关联物品（2026-10-10）

- 在「人物资料」选择住宅后，会自动生成一条独立的「住宅」类别物品，标题显示「住宅」「自动关联」两个标签，带入规则库对应的名称、常备点数、使用时点和完整解说。
- 自动住宅物品和自动生活方式物品可以同时存在，费用都会计入剩余常备化点数。更换或清空住宅时，只更新或删除系统生成的住宅物品；手动添加的物品和生活方式物品不会被误删。
- 这两类自动物品都需要在人物资料页更改，不能直接删除或编辑；旧人物 JSON／IndexedDB 存档保持兼容。若先前手动添加过相同住宅项目，请自行检查以避免重复计算费用。

## 本次更新：物品清单长文本布局（2026-10-10）

- 「物品管理」已将原来需要横向滚动的超宽单行表格，改成每件物品独立的档案卡片：名称、类别、时点、对象、难易度、常备/件、数量、已用数量按统一网格对齐；“完整效果／规则说明／备注”占据整张卡片的宽度。
- 自行添加的物品效果现在使用可输入多行的 `textarea`，会在首次显示、输入长文本以及调整浏览器窗口宽度时根据内容自动扩展高度，不再被单行输入框截断。自动关联的生活方式条目也以相同的整行展示区显示完整效果，但只能在人物资料页调整。
- 手机窄屏自动切换竖向字段排列，避免整页横向滚动。保留原有 `items[].effect`、`items[].cost` 等字段和数据导入导出方式，与旧版存档兼容。

## 本次更新：多人物档案库（2026-10-10）

- 首次使用时会在浏览器内创建 `IndexedDB` 人物档案库。之前使用 `localStorage` 自动保存的单人物档案，会在数据库首次初始化时**自动导入为一份独立人物档案**。为了安全，旧 `localStorage` 备份不会在迁移时删除。
- 左侧新增「人物档案库」页面，可**创建人物、打开切换、复制人物、重命名、删除人物**。人物有自己的唯一 ID；各自的头像、机体图、仆从头像、装备库、装备组、类别、特技和 Combio 都独立保存，切换人物会先完成当前档案保存。
- 「批量备份所有人物」会导出 `gsk-web-library-v1` 格式 JSON，包含完整人物数据和压缩图片。原有「下载当前人物存档」仍导出兼容 `gsk-web-character-v1` 格式。
- 「导入 JSON 人物 / 档案库」支持旧版单人物 JSON 和新版批量 JSON；均**作为新档案导入**，不会覆盖已有角色，且会生成新的本地 ID。建议定期批量备份，尤其是清理浏览器缓存、更换设备、改域名或浏览器前。
- 静态 GitHub Pages **无需后端**即可管理多人物，但不能跨设备实时同步。IndexedDB 数据仅保存在当前浏览器 / 当前站点来源。清除站点数据会同时清除人物库；务必另行保存 JSON 文件。私密角色档案请勿上传到公开代码仓库。
- 如果浏览器禁止 IndexedDB（例如某些隐私模式或特殊文件打开环境），界面会显示警告并退回旧版单人物本地存储。请在正常浏览器的 GitHub Pages HTTPS 地址使用，并备份数据。

## 前次更新（2026-10-10）

- **仆从头像**：在「仆从资料」中，每个仆从均有独立头像上传、更换、移除按钮。图片采用原有浏览器压缩流程，记录在 `servants[i].image` 中，随 JSON 存档备份、导入恢复；历史存档的仆从无需迁移即可继续使用。头像也会加入 PNG / PDF 的仆从附录（前 20 名）。请注意多张图片可能占满浏览器本地存储，及时备份 JSON。
- **生活方式自动物品**：在「人物资料」中选择生活方式后，「物品管理」会出现自动关联的规则物品，包含名称、生活方式类别、常备化费用与原表解说。费用计入剩余常备点；切换或清除生活方式会仅替换/移除自动记录，不修改玩家自己录入的物品。关联行不可直接编辑或删除，需回人物资料更换。原先自行录入过同名物品的旧档案请手动检查，以免重复计费。
- **离线 PDF**：在「导出指令 → 档案总览图导出」点击「导出 A4 PDF」，将 PNG 档案使用的内容分割成多页 A4 PDF 下载，无需 CDN 或打印驱动。PDF 是**图片型 PDF**，不是可选字的文本 PDF。特别长的背景段落会增加页数；分享前请检查排版。

## 本版新增

- **类别与等级**：界面统一称为「类别」；类别成长页显示初始等级合计、成长等级合计、角色总体等级。初始等级合计不得超过 3，全部类别累计等级不得超过 20，输入非负整数；非法输入会恢复旧值。加载旧存档时，超出限制的数值会按三个类别依次截断到允许范围，请备份旧存档后升级。
- **身份预览**：人物资料中的机体登记显示「机体名称 [类别1名称]」；背景概述与详细信息均会显示在人物预览中。导出 PNG 时会附加完整的这两段文字，画布长度随内容增加。
- **批注提示**：删除与自定义悬浮说明重复的浏览器原生 `title` 提示；数值与规则批注统一使用固定定位的提示框，并避开浏览器边缘。手机端点按即可查看。
- **装备型号**：新增装备时可同时填「装备名称」和「型号（规则书名称）」，未填写型号时默认等于名称；编辑器可以修改名称、型号。装备 JSON 导出也携带型号字段。
- **出身关联特技**：选出身后，自动填入对应的泛用特技；更改出身时仅替换自动关联条目，其他玩家自填特技不变。53 个出身中「玩家自行决定」无固定关联；两条同名「天涯孤独」会列出各自关联特技，以便区分。
- **命名装备组**：在机体配装页面将所有装备槽保存为装备组（可以新建、覆盖、切换、删除），对现有装备库无破坏；导出页会为每个装备组显示独立的 `.SvW W装备组名称{JSON}` 指令。请**逐条复制并向骰子发送**，不要合并成一条。

## 使用说明

1. 打开 `index.html`，先在「人物档案库」创建人物或导入旧人物 JSON，然后在「人物资料」登记信息与上传头像。
2. 在「类别成长」设置初始 / 成长等级，在「机体配装」创建装备、设定型号、保存多个装备组。
3. 在「特技与加护」查看自动关联的出身泛用特技，并自由添加其他技能；可到「仆从资料」添加 NPC 并上传头像。
4. 在「导出指令」逐条复制装备组 `.SvW` 指令，也可以下载 PNG、A4 PDF 或单人物 JSON；在「人物档案库」还可以批量备份全部人物。

## 数据与兼容性

- 在同一浏览器与域名下，多人物数据自动保存在 `IndexedDB` 中；旧版 `localStorage` 仅作为首次迁移来源或 IndexedDB 不可用时的单人物后备。更换设备时需要导出并导入 JSON，静态网页**不具备自动云同步**。
- **不要将私人人物 JSON 存档上传到公开 GitHub 仓库。**
- 旧版 `gsk-web-character-v1` 存档可导入为新人物，新版批量使用 `gsk-web-library-v1`；现有字段继续保留；新增 `equipmentSets`、`activeEquipSet`、`meta.originIndex` 和自动出身特技标记。
- 自动关联的特技条目可自行编辑，但更换出身会替换该条目；玩家自己建立的特技不受影响。
- 条件型特技效果不会自动加到战斗数值，仍须结合原 Excel / GM 规则校验；导出的机器人指令是否接受扩展的「型号」字段需按骰子实际接口验证。
- PNG 不是整个网页截图，包含人物及机体影像、类别属性、主要战斗数值、关键装备、特技摘要，以及完整背景概述 / 详细信息。特别长的文本可能生成高度很大的图片。

## 部署 GitHub Pages

将 `index.html` 放在仓库根目录，在仓库 `Settings → Pages → Deploy from a branch` 中选择 `main` 和 `/ (root)`。如果替换后仍显示旧界面，清除缓存或按 `Ctrl+F5` 强制刷新。

## 包含文件

- `index.html`：运行只需要这一个文件。
- `source/app.js`：编辑逻辑、导出与前端交互。
- `source/styles.css`：档案风格与移动端样式。
- `source/data.json`：基础规则、职业类别（源自原表）、成长表、特技与装备模板。
- `template.html`：用于把三份源文件内嵌成单文件 HTML 的页面模板。

## 物品卡折叠与类别标题（本次更新）

- 「物品管理」现在与特技一样使用可折叠档案卡。点击标题即可独立展开或收起，关闭时不占据大块表单空间。
- 标题在物品名后展示独立的浅棕色类别标签（不再使用方括号）；未填写时显示「未分类」。生活方式自动添加的物品除「生活方式」类别标签外，保留「自动关联」标记。
- 展开后可以编辑名称、类别、时点、对象、难易度、常备点数、数量、已用数量和完整效果。自动关联的生活方式物品仍是只读。
- 手工新增物品默认展开；多个物品可同时展开。改变常备点数/数量触发重算时，已展开状态保持不变。
- 原物品效果的自动增高、手机端响应式布局、IndexedDB 多人物存储以及 JSON 备份格式均保留。
